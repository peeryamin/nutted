How it works

Three steps. The browser you already use, the target you already have open.

  1. 1

    Open the target, confirm scope

    Tell BugSeek which program and scope you're working under. Out-of-scope hosts and endpoints are excluded before anything runs — scope is enforced, not suggested.

  2. 2

    Scan

    Passive recon runs instantly: tech fingerprinting, security headers, cookie audit, JS secret scanning, DOM analysis. With your explicit authorization, the guided agent plans and executes active tests — XSS, IDOR, CORS, auth issues, GraphQL — with confirmed findings marked as such and the rest surfaced as review hints, not scanner guesses.

  3. 3

    Review & export

    Findings arrive with severity, CVSS, evidence, and a trap-probability score. Export a platform-ready report draft, review it, and submit it yourself. Human judgment stays in the loop — platforms require it.

The easier a finding looks, the more suspicious you should be. BugSeek scores every finding for trap probability — canary tokens, too-easy reflections, behavioral anomalies, known decoy signatures — so you don't burn a submission (or your reputation) on a honeypot.

Why a browser extension?

Serious autonomous pentesting already exists — we're not pretending it doesn't. Strix (~66k GitHub stars) is the benchmark for open-source agent pentesting; XBOW and Pentera are $1B+ companies in the enterprise lane; Burp Suite Pro ($449/yr) remains the expert's workbench. BugSeek doesn't try to out-agent them. It meets the individual hunter where the target already is: the browser.

Zero setup

No Docker, no LLM keys, no CLI. Install the extension, open the target, scan. The hunters who find the most bugs aren't always the ones who enjoy configuring tooling.

Hunter workflow, not dev workflow

Scope confirmation → scan → platform-ready report. Not compliance PDFs for auditors — HackerOne fields, Bugcrowd VRT mapping, PoC evidence checklists.

Trap detection

No major agent we evaluated advertises honeypot or canary detection. Automation without it is a reputation risk; we built it in from Phase 2.

Pricing that respects how hunters actually work

Metered by scan credits, not "unlimited" promises. Passive scans are cheap; guided agent scans cost real model compute — so we price them honestly instead of hiding it.

Questions hunters actually ask

Is this legal? Can I point it at any website?

No — and BugSeek won't let you pretend otherwise. Passive recon only analyzes what the page already shows your browser. Active testing requires you to explicitly confirm authorization: a bug bounty program scope, a pentest contract, or a target you own. Out-of-scope hosts are blocked before any test runs. Unauthorized access is a crime in most jurisdictions (including under India's IT Act, 2000 §66). Our Terms of Service and Responsible Disclosure policy spell this out — read them.

Does BugSeek submit reports to HackerOne/Bugcrowd automatically?

No. No bounty platform supports automated report submission, and bulk automation risks account penalties. BugSeek generates a fully formatted draft — title, severity/CVSS or VRT category, weakness, steps to reproduce, impact, PoC evidence checklist — and you review and submit it. That's a deliberate design decision, not a missing feature.

What data leaves my machine?

Passive recon runs locally in the extension. When you run a guided agent scan, the page context needed for testing is sent to our backend API over TLS — never credentials, cookies' secret values, or PII found during testing. Findings reference the vulnerability; they don't reproduce sensitive data. See the ToS for the full data-handling commitments.

How is this different from Burp Suite / Nuclei / Strix?

Burp Pro ($449/yr) is the expert's proxy workbench — powerful, steep learning curve, desktop-bound. Nuclei is the gold standard for signature-based known-vuln scanning with ~12k community templates. Strix is the benchmark open-source autonomous pentest agent (~66k stars) — but it's a developer-first CLI. BugSeek is none of those: it's a browser-native hunter workflow — zero setup, scope-first, trap-aware, with reports shaped for bounty platforms instead of compliance auditors.

Will it be on the Chrome Web Store?

That's the plan for the passive-recon Phase 1 build — passive analysis extensions (like Wappalyzer) are demonstrably publishable. Active testing is a policy grey zone we're navigating carefully: agent logic lives in our backend API (which Chrome's Manifest V3 remote-code rules explicitly allow), and active features stay behind an authorization-gated flow. If the store path closes, we'll distribute via direct install — the extension is built to work either way.

Is BugSeek open source?

We're still deciding — it's one of the biggest strategic questions we have. The case for open-sourcing the extension client (à la Strix's Apache-2.0 playbook) is real: trust, distribution, community contributions. The case against is that our moat — the agent, honeypot models, and report intelligence — needs protection while we're small. Our current thinking is documented in the business plan; whatever we choose, the free tier stays genuinely useful.
